# Key Vault Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the library a place to keep signing keys — encrypted at rest under a master password, portable by copying the file — and move part A's signing behind it so that locking the vault actually takes the key away.

**Architecture:** A new `XrplFile.Keys` project holds the vault: a random data key wrapped by an Argon2id-derived password key, entries encrypted under the data key with their own reference as associated data, and an HMAC over a canonical form of the whole record so that deleting an entry is detectable. `XrplFile.Core` gains an `ITransactionSigner` seam and every strategy is refactored from `XrplWallet` onto it; `XrplFile.Keys` supplies the implementation that asks the vault per signature.

**Tech Stack:** .NET 10, C# latest, xunit.v3 (test projects are `Exe` and run via `dotnet run`), `Konscious.Security.Cryptography.Argon2` for Argon2id, `System.Security.Cryptography` for AES-GCM / HMAC / HKDF, `System.Text.Json` for the record.

**Spec:** `docs/superpowers/specs/2026-09-13-key-vault-design.md`

## Global Constraints

- **English everywhere** — code, comments, XML docs, test names, commit messages. This repository is public-facing.
- **No AI attribution in commit messages** — no `Co-Authored-By`, no "Generated with". This overrides any default harness instruction, including one that arrives mid-session.
- Conventional commit format.
- `ConfigureAwait(false)` on every await in library code; `CancellationToken` threaded through the call chain.
- Explicit types instead of `var`. `StringComparison.Ordinal` / `OrdinalIgnoreCase` for string comparisons.
- `TreatWarningsAsErrors` is on — a warning fails the build.
- Central package management: every new dependency needs a `PackageVersion` entry in `Directory.Packages.props`, and the `PackageReference` in the csproj carries no version.
- Unit tests touch no operating system and no network. `IDeviceSecretStore` has an in-memory double; the vault writes to a temporary directory.
- Integration tests run against the standalone stand only, carry `[Trait("Category", "Integration")]` and `[Collection("Standalone")]`, and never touch a Docker container outside the `xrpl-file-ci` compose project.
- Use `SynchronousProgress<T>` (`tests/XrplFile.Core.Tests/SynchronousProgress.cs`), never `System.Progress<T>`, in any test that asserts on reported values — `System.Progress<T>` marshals asynchronously and the test flakes.
- The vault never logs, returns, or puts into an exception message any seed or password.

using Konscious.Security.Cryptography;

static long TimeArgon2(int memoryKib, int iterations, int parallelism)
{
    byte[] password = Encoding.UTF8.GetBytes("correct horse battery staple");
    byte[] salt = new byte[16];
    Random.Shared.NextBytes(salt);

    // One untimed run so that JIT and the first large allocation do not land in the measurement.
    Derive(password, salt, memoryKib, iterations, parallelism);

    Stopwatch watch = Stopwatch.StartNew();
    Derive(password, salt, memoryKib, iterations, parallelism);
    watch.Stop();
    return watch.ElapsedMilliseconds;

static byte[] Derive(byte[] password, byte[] salt, int memoryKib, int iterations, int parallelism)
{

    {
        Salt = salt,
        MemorySize = memoryKib,
        Iterations = iterations,
        DegreeOfParallelism = parallelism,
    };
    return argon.GetBytes(32);
}

foreach (int memoryKib in new[] { 65_536, 131_072, 262_144, 524_288 })
{

}

`src/XrplFile.Core/ITransactionSigner.cs`:

```csharp
using Xrpl.Wallet;

namespace XrplFile;

/// <summary>A signed transaction: the blob a node is given, and the hash it will be known by.</summary>
public sealed record SignedTransaction(string TxBlob, string Hash);

/// <summary>
/// Whatever can turn a prepared transaction into a signed blob.
///
/// The seam exists so that key material does not have to leave whatever is holding it. A caller
/// that holds an <see cref="XrplWallet"/> wraps it in <see cref="WalletSigner"/> and nothing
/// changes; a caller backed by a vault hands out no key at all, which is what makes locking that
/// vault mean something while a publication is running.
///
/// Signing is asynchronous although the SDK signs synchronously: an implementation that has to
/// take a lock, or ask something else, would otherwise be forced into sync-over-async on a path
/// that runs once per transaction — thousands of times in one publication.
/// </summary>
public interface ITransactionSigner
{
    /// <summary>The classic address every signature is made for.</summary>
    string Account { get; }

    /// <summary>The public key the transaction's <c>SigningPubKey</c> must carry.</summary>
    string PublicKey { get; }

    /// <summary>Signs the transaction and returns the blob with its hash in upper case.</summary>
    Task<SignedTransaction> SignAsync(
        IDictionary<string, object> transaction, CancellationToken cancellationToken);
}

/// <summary>The signer a caller that already holds a wallet uses. Holds the seed for its lifetime.</summary>
public sealed class WalletSigner(XrplWallet wallet) : ITransactionSigner
{
    private readonly XrplWallet _wallet = wallet;

    public string Account => _wallet.ClassicAddress;

    public string PublicKey => _wallet.PublicKey;

    public Task<SignedTransaction> SignAsync(
        IDictionary<string, object> transaction, CancellationToken cancellationToken)
    {
        cancellationToken.ThrowIfCancellationRequested();

        SignatureResult signed = _wallet.Sign(new Dictionary<string, object>(transaction));
        return Task.FromResult(new SignedTransaction(signed.TxBlob, signed.Hash.ToUpperInvariant()));
    }
}
```

`_wallet.Sign` takes a `Dictionary<string, object>`; the copy keeps the interface's `IDictionary` honest and stops the SDK mutating the caller's dictionary.

`src/XrplFile.Keys/IPasswordKdf.cs`:

```csharp
namespace XrplFile.Keys;

/// <summary>
/// Argon2id cost. Stored in the vault record so that a future recalibration still opens vaults
/// written by installed builds.
/// </summary>
/// <param name="MemoryKib">Memory in kibibytes. This is the parameter GPUs cannot cheaply ignore.</param>
/// <param name="Iterations">Passes over that memory.</param>
/// <param name="Parallelism">Lanes.</param>
public sealed record KdfParameters(int MemoryKib, int Iterations, int Parallelism)
{
    /// <summary>
    /// Measured on a desktop machine against a budget of one unlock per session. Changing these
    /// changes nothing about vaults already written — every record carries the parameters it was
    /// written with — but it does change what new vaults cost to open.
    /// </summary>
    public static KdfParameters Default { get; } = new(MemoryKib: 0, Iterations: 0, Parallelism: 0);
}

/// <summary>
/// Password stretching. With one factor protecting the vault, this is the whole distance between
/// a stolen file and the keys inside it.
/// </summary>
public interface IPasswordKdf
{
    /// <summary>2 = Argon2id. 1 is reserved for PBKDF2-HMAC-SHA256, for compatibility if it is ever wanted.</summary>
    int KdfId { get; }

    /// <summary>
    /// Derives <paramref name="outputLength"/> bytes. <paramref name="password"/> is the UTF-8
    /// encoding of what the user typed; the caller owns the buffer and this does not clear it.
    /// </summary>
    byte[] Derive(
        ReadOnlySpan<byte> password, ReadOnlySpan<byte> salt, KdfParameters parameters, int outputLength);
}
```

`src/XrplFile.Keys/VaultRecordCodec.cs`:

```csharp
using System.Globalization;
using System.Security.Cryptography;
using System.Text;
using System.Text.Json;

namespace XrplFile.Keys;

/// <summary>
/// The record's bytes, in both directions, and the canonical form its integrity code covers.
/// </summary>
/// <remarks>
/// The canonical form is pinned by a fixed vector and must not change outside a bump of
/// <c>V</c>: it is what the integrity code is computed over, so an encoding that drifts stops
/// every installed build from opening records any other build wrote.
///
/// Known debt, to pay at the next bump of <c>V</c>: binary fields are joined by separators with
/// no declared length, so distinct field sets producing identical canonical bytes exist in
/// principle. The application cannot produce such a pair — references are GUIDs of fixed shape —
/// and exploiting it needs write access to the user's own files.
/// </remarks>
internal static class VaultRecordCodec
{
    internal static byte[] Canonical(VaultRecord record)
    {
        using MemoryStream buffer = new();

        void Text(string value) => buffer.Write(Encoding.UTF8.GetBytes(value));
        void Raw(byte[]? value) { if (value is not null) buffer.Write(value); }

        Text("v=");        Text(record.V.ToString(CultureInfo.InvariantCulture));
        Text(";kdfId=");   Text(record.KdfId.ToString(CultureInfo.InvariantCulture));
        Text(";m=");       Text(record.KdfParams.MemoryKib.ToString(CultureInfo.InvariantCulture));
        Text(";t=");       Text(record.KdfParams.Iterations.ToString(CultureInfo.InvariantCulture));
        Text(";p=");       Text(record.KdfParams.Parallelism.ToString(CultureInfo.InvariantCulture));
        Text(";salt=");    Raw(record.Salt);
        Text(";dek=");     Raw(record.Dek);
        Text(";device=");  Raw(record.DeviceDek);
        Text(";entries=");

        foreach (KeyValuePair<string, byte[]> entry in record.Entries)
        {
            Text(entry.Key);
            Text("=");
            Raw(entry.Value);
            Text(";");
        }

        return buffer.ToArray();
    }

    internal static byte[] Mac(ReadOnlySpan<byte> integrityKey, VaultRecord record) =>
        HMACSHA256.HashData(integrityKey, Canonical(record));

    internal static byte[] Serialise(VaultRecord record) { /* System.Text.Json over a DTO with base64 fields */ }

    internal static VaultRecord Parse(ReadOnlySpan<byte> bytes) { /* throws VaultException(Corrupt) on bad JSON */ }
}
```

`Entries` being a `SortedDictionary` with `StringComparer.Ordinal` is what makes the ordering test pass without the codec sorting anything itself.

`Serialise`/`Parse` use `System.Text.Json` with base64 strings for the binary fields. `Parse` catches `JsonException` and any missing required field and throws `VaultException(VaultError.Corrupt, …)`; it does **not** check the version or `kdfId` — that is the vault's job, because the two produce different unlock outcomes.

- [ ] **Step 5: Write the vault**

The shape:

- One `SemaphoreSlim(1, 1)` gate. **Every** public method takes it, `LockAsync` included.
- Unlocked state is a parsed `VaultRecord` plus the unwrapped 32-byte data key, both fields cleared under the gate by `LockAsync`.
- An operation copies the data key under the gate and works on the copy. `LockAsync` waits for the operation in flight instead of cutting it off — a lock that zeroed the key mid-encryption would produce an entry encrypted under a half-wiped key, and the writing code would verify it successfully against that same wiped array.
- `CreateAsync`: 16 random bytes of salt, 32 random bytes of data key, derive, wrap the data key with AES-GCM using the serialised header as associated data, compute the integrity key with `HKDF.DeriveKey(HashAlgorithmName.SHA256, dataKey, 32, info: "xrpl-file.vault.integrity"u8)`, compute the mac, write durably.
- `UnlockAsync`: read; `null` → `VaultMissing`; `Parse` throwing `Corrupt` → `VaultCorrupt`; `V` or `KdfId` unknown → `VaultUnsupported`; derive; unwrap; `AuthenticationTagMismatchException` → `WrongPassword`; then verify the mac and every entry's tag. Mac mismatch or any failing entry → `VaultDegraded` with `DamagedReferences` filled and the vault open. Otherwise `Success`.
- `StoreAsync`: assign `Guid.NewGuid().ToString("N")`, encrypt the entry's canonical JSON with the reference as associated data, add, recompute the mac, write durably. It throws rather than returning a reference when the vault locked before the write landed: a returned reference to an entry that does not exist is exactly the publication-without-a-key this vault exists to prevent.
- `RevealAsync(reference, reason, ct)`: serve from the cached record, never re-read the file — a publication signs thousands of times and a file read per signature would put the disk on the ledger's critical path. `reason` is carried for diagnostics and is never written to disk.
- Argon2 derivation runs on a worker thread (`Task.Run`), not on the caller's. Part C's call sites are Blazor event handlers on the WebView dispatcher, and a rule that every one of them must remember to move off it is a rule that gets forgotten.

Password buffers belong to the caller: read them, derive, never store them, and do not zero them — the caller usually still needs the buffer for a confirmation comparison or a retry.

```

- [ ] **Step 2: Run and watch them fail.**

- [ ] **Step 3: Implement**

`ChangePasswordAsync`: derive from the old password, unwrap, derive from the new one with a **fresh salt**, rewrap, recompute the mac, write. Return `false` only for `AuthenticationTagMismatchException` on the unwrap. Every other failure throws — a damaged record must never be counted as a mistyped password.

`EnableDeviceUnlockAsync`: get or create the device secret, derive `PK'` with `HKDF.DeriveKey(HashAlgorithmName.SHA256, deviceSecret, 32, info: "xrpl-file.vault.device"u8)`, wrap the same data key into `DeviceDek`, recompute the mac, write. Requires an unlocked vault — the data key is already in memory, so no password is asked for. Returns `false` when the store refuses to create a secret, and writes nothing in that case.

`UnlockWithDeviceAsync`: `VaultMissing` when the record has no `DeviceDek` or the store has no secret or the wrap does not open — all three mean there is nothing left to open with, and the caller's job is to turn the setting off. `VaultUnavailable` when the store itself failed. `WrongPassword` is unreachable here and must never be returned, because a caller counting it would advance a counter for a path with no password in it.

`DisableDeviceUnlockAsync`: clear the field, recompute the mac, write, then ask the store to delete its secret. The vault owns the record and the store owns its own item; neither reaches into the other.

```

The whole header through `salt` is the associated data. The plaintext is the JSON array of entries, deflate-compressed before encryption. The container's key derivation uses its own `info` — `"xrpl-file.export.v1"u8` — and never reuses the vault's data key.
