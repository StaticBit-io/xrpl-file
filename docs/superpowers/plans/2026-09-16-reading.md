# Reading a link back into a file (part C4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the application a Read tab that takes an `xrpl-file://` link, shows what the file is before downloading it, reads it block by block with progress, and saves it to disk — with nothing incomplete ever reaching the place the person chose.

**Architecture:** The application drives the block loop itself so it can report progress and be cancelled, but every cryptographic check stays in `XrplFile.Core`'s reader. Blocks are streamed into a temporary file and handed to the save dialog only once the whole file has verified. Every decision lives in a model in `app/XrplFile.App.Core`, tested on Linux against the fake ledger.

**Tech Stack:** .NET 10, C# latest, xUnit v3 (`xunit.v3`, built-in `Assert`), MAUI Blazor Hybrid (Windows), `XrplFile.Core`'s `XrplFileReader`.

**Spec:** `docs/superpowers/specs/2026-09-16-reading-design.md`

```csharp
    /// <inheritdoc/>
    public async Task<bool> SaveStreamAsync(string suggestedFileName, Stream content, CancellationToken cancellationToken)
    {
        ArgumentException.ThrowIfNullOrWhiteSpace(suggestedFileName);
        ArgumentNullException.ThrowIfNull(content);

        FileSavePicker picker = new()
        {
            SuggestedFileName = suggestedFileName,
        };

        string extension = Path.GetExtension(suggestedFileName) is { Length: > 0 } value ? value : ".bin";
        picker.FileTypeChoices.Add("File", [extension]);

        InitializeWithWindow.Initialize(picker, GetActiveWindowHandle());

        StorageFile? file = await picker.PickSaveFileAsync().AsTask(cancellationToken).ConfigureAwait(false);

        if (file is null)
        {
            return false;
        }

        // OpenStreamForWriteAsync rather than FileIO.WriteBytesAsync: the caller's content is
        // already a file on disk, and bringing a whole file into an array to hand it over would
        // undo the reason it was streamed there in the first place.
        await using Stream destination = await file.OpenStreamForWriteAsync().ConfigureAwait(false);
        destination.SetLength(0);
        await content.CopyToAsync(destination, cancellationToken).ConfigureAwait(false);

        return true;
    }
```

`OpenStreamForWriteAsync` is an extension on `StorageFile` from `System.IO`; the file already has
`using System.Runtime.InteropServices.WindowsRuntime;` and `using Windows.Storage;`. If the
extension does not resolve, the namespace it needs is `System.IO` — check what the file already
imports and add only what is missing. `SetLength(0)` matters: the picker may hand back an existing
file, and a shorter new file would otherwise leave the old tail behind.

```csharp
namespace XrplFile.App.Core;

/// <summary>
/// What a person is told when reading a link fails (design 4.3). Deliberately not
/// <see cref="PublishErrorMessages"/>: the same <see cref="XrplFileError"/> values mean different
/// things depending on which side of the ledger you are standing on. To a publisher
/// <see cref="XrplFileError.BlockMismatch"/> means the ledger did not return what was just written
/// to it; to a reader it means the file that is in the ledger does not match its own manifest, and
/// nobody wrote anything just now.
/// </summary>
public static class ReadErrorMessages
{
    public static string For(XrplFileError error) => error switch
    {
        XrplFileError.InvalidLink =>
            "That is not an xrpl-file link.",
        XrplFileError.ManifestNotFound =>
            "This network has no transaction at that hash. The link may be wrong, or it may belong to a different network.",
        XrplFileError.NodeLacksHistory =>
            "This node's history does not reach back far enough to hold the file. A node that keeps more history can read it.",
        XrplFileError.CorruptManifest =>
            "There is something at that hash, but it is not a file description this version understands.",
        XrplFileError.ListMismatch =>
            "The list of the file's blocks does not match what the file's own description says it should be. Nothing was saved.",
        XrplFileError.BlockMismatch =>
            "A block of the file does not match what the file's own description says it should be. Nothing was saved.",
        XrplFileError.ChunkMissing =>
            "Part of the file is not in the ledger. Nothing was saved.",
        XrplFileError.TooLarge =>
            "This file is larger than this application will read.",
        XrplFileError.NodeUnreachable =>
            "The node did not answer. Check the node URL in Settings and try again.",
        XrplFileError.InsufficientBalance or XrplFileError.BudgetExceeded or XrplFileError.FeeMismatch
            or XrplFileError.SubmitRefused or XrplFileError.ValidationTimeout or XrplFileError.ResumeMismatch
            or XrplFileError.SessionAlreadyRun =>
            "Something went wrong that reading a file cannot cause. This is a defect in this application, not something you did.",
        _ => throw new ArgumentOutOfRangeException(nameof(error), error, "no sentence for this error"),
    };

    /// <summary>The same sentence, with the block named when the library said which one.</summary>
    public static string For(XrplFileException exception)
    {
        ArgumentNullException.ThrowIfNull(exception);

        string sentence = For(exception.Error);
        return exception.Block is int block ? $"{sentence} (block {block})" : sentence;
    }
}
```

The seven publishing errors deliberately share one sentence, so
`Every_sentence_is_its_own` would fail. **That is the point at which you discover the test and the
code disagree, and the code is right:** grouping them is honest, because to a reader they are one
situation — a defect. Change that test to assert distinctness across the ten errors reading can
actually produce, and say in a comment why the other seven are excluded. Do not split the sentence
seven ways to satisfy a test.

```csharp
namespace XrplFile.App.Core;

/// <summary>
/// The first half of reading (design 4.1): the link, and what the ledger says the file is. The
/// manifest costs one transaction lookup and carries the name, the size and the type, so a person
/// sees what they are about to download before any of it moves (design H1).
/// </summary>
public sealed class ReadModel(IConnectionFactory connections, INodeSettingsStore nodes)
{
    /// <summary>
    /// The largest file this application reads — <see cref="ReaderOptions.MaxBytes"/>'s own default.
    /// With the file streamed to disk rather than held in memory this is policy rather than
    /// architecture (design H7): what argues against raising it is the node, not this application.
    /// Two hundred megabytes is roughly two hundred thousand requests.
    /// </summary>
    public const long MaxBytes = 20_000_000;

    private long _ceiling = MaxBytes;

    public string Link { get; set; } = string.Empty;

    public XrplFileLink? Parsed { get; private set; }

    public ManifestRecord? Manifest { get; private set; }

    /// <summary>The node the manifest came from, which is also the node the blocks will come from.</summary>
    public string? NodeUrl { get; private set; }

    public string? Message { get; private set; }

    public bool CanRead => Manifest is not null && Message is null;

    /// <summary>The ceiling, so a size refusal can be tested without publishing a large file.</summary>
    internal void SetCeilingForTests(long ceiling) => _ceiling = ceiling;

    public void Clear()
    {
        Parsed = null;
        Manifest = null;
        NodeUrl = null;
        Message = null;
    }

    /// <summary>
    /// Parses the link, finds the node for its own network, and fetches the manifest. Sets
    /// <see cref="Message"/> and leaves <see cref="CanRead"/> false when any of that cannot be done.
    /// </summary>
    public async Task LookUpAsync(CancellationToken cancellationToken)
    {
        Clear();

        if (!XrplFileLink.TryParse(Link, out XrplFileLink? parsed))
        {
            Message = ReadErrorMessages.For(XrplFileError.InvalidLink);
            return;
        }

        Parsed = parsed;

        // The link names its own network, so nothing else is asked and nothing else may disagree
        // (design H9).
        if (NodeEndpoint.Resolve(nodes, parsed.Network) is null)
        {
            Message =
                $"No node URL is known for the network '{parsed.Network}'. Add one in Settings.";
            return;
        }

        try
        {
            await using ILedgerConnection connection =
                await connections.ConnectAsync(parsed.Network, cancellationToken).ConfigureAwait(false);

            NodeUrl = connection.Url;

            XrplFileReader reader = new(connection.Source, new ReaderOptions { MaxBytes = _ceiling });
            ManifestRecord record = await reader.ManifestAsync(parsed, cancellationToken).ConfigureAwait(false);

            Manifest = record;

            // Refused here rather than in the run, so the person is told before they agree rather
            // than after they have waited.
            if (record.Manifest.Size > _ceiling)
            {
                Message = ReadErrorMessages.For(XrplFileError.TooLarge);
            }
        }
        catch (XrplFileException ex)
        {
            Message = ReadErrorMessages.For(ex);
        }
    }
}
```

```csharp
namespace XrplFile.App.Core;

/// <summary>
/// The block loop (design 4.2). It drives <see cref="XrplFileReader"/>'s per-block methods itself
/// rather than calling <see cref="XrplFileReader.ReadAsync"/>, so the screen can show progress and
/// the person can stop (design H2) — but every cryptographic check stays in the library
/// (design H3): <see cref="XrplFileReader.BlockListAsync"/> verifies the block list against the
/// manifest's root and <see cref="XrplFileReader.BlockAsync"/> verifies each block against its own
/// hash. Nothing here hashes anything.
///
/// It is deliberately a much smaller thing than <see cref="PublicationRun"/>: no state file, no
/// history, no generation pinning, no resumption. The reason is one sentence — a read costs nothing
/// and can simply be started again, and an interrupted publication cannot.
/// </summary>
public sealed class ReadRun(IConnectionFactory connections, IFilePickerService picker)
{
    private readonly Lock _gate = new();

    private CancellationTokenSource? _cancellation;
    private ReadState _state = ReadState.Idle;
    private int _blocksDone;
    private int _blocksTotal;
    private long _bytesDone;
    private long _bytesTotal;
    private string? _name;
    private string? _failure;
    private bool _saved;
    private string? _temporary;

    public Task Completion { get; private set; } = Task.CompletedTask;

    public ReadSnapshot Snapshot
    {
        get
        {
            lock (_gate)
            {
                return new ReadSnapshot(
                    _state, _blocksDone, _blocksTotal, _bytesDone, _bytesTotal, _name, _failure, _saved);
            }
        }
    }

    /// <summary>Where the blocks are being written. Exists so a test can prove it is cleaned up.</summary>
    internal string? TemporaryPathForTests
    {
        get { lock (_gate) return _temporary; }
    }

    /// <summary>Starts a read. <see langword="false"/> when one is already going.</summary>
    public bool Start(XrplFileLink link, ManifestRecord manifest)
    {
        ArgumentNullException.ThrowIfNull(link);
        ArgumentNullException.ThrowIfNull(manifest);

        CancellationTokenSource cancellation = new();

        lock (_gate)
        {
            if (_state == ReadState.Running)
            {
                cancellation.Dispose();
                return false;
            }

            DeleteTemporary();

            _cancellation?.Dispose();
            _cancellation = cancellation;
            _state = ReadState.Running;
            _blocksDone = 0;
            _blocksTotal = manifest.Manifest.Blocks;
            _bytesDone = 0;
            _bytesTotal = manifest.Manifest.Size;
            _name = manifest.Manifest.Name;
            _failure = null;
            _saved = false;
            Completion = Task.Run(() => RunAsync(link, manifest, cancellation.Token));
        }

        return true;
    }

    public void Cancel()
    {
        lock (_gate) _cancellation?.Cancel();
    }

    /// <summary>Cancels and waits for the read to stop. What the window-close handler calls.</summary>
    public async Task<bool> StopAsync(TimeSpan timeout)
    {
        Task running;
        lock (_gate)
        {
            _cancellation?.Cancel();
            running = Completion;
        }

        if (!running.IsCompleted)
        {
            Task finished = await Task.WhenAny(running, Task.Delay(timeout)).ConfigureAwait(false);
            if (!ReferenceEquals(finished, running)) return false;
        }

        Reset();
        return true;
    }

    /// <summary>
    /// Hands the finished file to the save dialog. Only a succeeded read has anything to save: the
    /// temporary file of a failed or cancelled one is incomplete, and nothing incomplete reaches
    /// the place the person chose (design H4).
    /// </summary>
    public async Task SaveAsync(CancellationToken cancellationToken)
    {
        string path;
        string suggested;

        lock (_gate)
        {
            if (_state != ReadState.Succeeded || _temporary is null) return;

            path = _temporary;

            // A file may have been published with no name at all: Manifest.Name is nullable. A
            // suggestion derived from nothing is still better than an empty dialog.
            suggested = string.IsNullOrWhiteSpace(_name) ? "xrpl-file.bin" : _name;
        }

        await using FileStream content = new(path, FileMode.Open, FileAccess.Read, FileShare.Read);
        bool saved = await picker.SaveStreamAsync(suggested, content, cancellationToken).ConfigureAwait(false);

        lock (_gate) _saved = saved;
    }

    /// <summary>Puts a finished read away and deletes what it left on disk.</summary>
    public void Reset()
    {
        lock (_gate)
        {
            if (_state == ReadState.Running) return;

            DeleteTemporary();
            _state = ReadState.Idle;
            _blocksDone = 0;
            _blocksTotal = 0;
            _bytesDone = 0;
            _bytesTotal = 0;
            _name = null;
            _failure = null;
            _saved = false;
        }
    }

    private async Task RunAsync(XrplFileLink link, ManifestRecord manifest, CancellationToken cancellationToken)
    {
        ReadState finalState;
        string? failure = null;

        try
        {
            await using ILedgerConnection connection =
                await connections.ConnectAsync(link.Network, cancellationToken).ConfigureAwait(false);

            // One of the four things that moved out of ReadAsync (design 3.1). EarliestLedgerAsync
            // is public on ILedgerSource, so this needs nothing added to the library.
            long? earliest = await connection.Source.EarliestLedgerAsync(cancellationToken).ConfigureAwait(false);

            if (earliest is long first && first > manifest.Manifest.FirstLedger)
            {
                throw new XrplFileException(
                    XrplFileError.NodeLacksHistory,
                    $"this node keeps history from ledger {first} and the file starts at {manifest.Manifest.FirstLedger}");
            }

            XrplFileReader reader = new(connection.Source);

            // Verified against the manifest's root inside the library before a single block is read.
            IReadOnlyList<BlockEntry> blocks =
                await reader.BlockListAsync(manifest, cancellationToken).ConfigureAwait(false);

            string temporary = Path.Combine(
                Directory.CreateTempSubdirectory("xrpl-file-read-").FullName, "download");

            lock (_gate)
            {
                _temporary = temporary;
                _blocksTotal = blocks.Count;
            }

            long written = 0;

            await using (FileStream file = new(temporary, FileMode.Create, FileAccess.Write, FileShare.None))
            {
                foreach (BlockEntry block in blocks)
                {
                    byte[] content = await reader.BlockAsync(manifest, block, cancellationToken).ConfigureAwait(false);
                    await file.WriteAsync(content, cancellationToken).ConfigureAwait(false);
                    written += content.Length;

                    lock (_gate)
                    {
                        _blocksDone++;
                        _bytesDone = written;
                    }
                }
            }

            // The last of the four. BlockAsync holds every block to the length the manifest implies
            // for it, so this can only fail if the block list did — which the library checked before
            // any block was read. Kept anyway: it is one comparison standing between a truncated
            // file and a file somebody is told is theirs.
            if (written != manifest.Manifest.Size)
            {
                throw new XrplFileException(
                    XrplFileError.BlockMismatch,
                    $"the blocks assemble to {written} bytes and the file's description says {manifest.Manifest.Size}");
            }

            finalState = ReadState.Succeeded;
        }
        catch (OperationCanceledException)
        {
            finalState = ReadState.Cancelled;
        }
        catch (XrplFileException ex)
        {
            finalState = ReadState.Failed;
            failure = ReadErrorMessages.For(ex);
        }
        catch (Exception ex) when (ex is IOException or UnauthorizedAccessException)
        {
            finalState = ReadState.Failed;
            failure = "The file could not be written to a temporary location while it was being read.";
        }
        catch (Exception)
        {
            finalState = ReadState.Failed;
            failure = "Something went wrong that this application does not have a specific message for.";
        }

        lock (_gate)
        {
            // A read that did not finish leaves nothing behind: its temporary file is a partial
            // download, and there is no honest use for one.
            if (finalState != ReadState.Succeeded) DeleteTemporary();

            _failure = failure;
            _state = finalState;
        }
    }

    /// <summary>Called under <see cref="_gate"/>. Removes the temporary file and the directory holding it.</summary>
    private void DeleteTemporary()
    {
        if (_temporary is null) return;

        try
        {
            Directory.Delete(Path.GetDirectoryName(_temporary)!, recursive: true);
        }
        catch (Exception ex) when (ex is IOException or UnauthorizedAccessException)
        {
            // Scratch in the operating system's temporary directory, which the system sweeps. A
            // file we could not remove is not worth failing a finished read over.
        }

        _temporary = null;
    }
}
```
